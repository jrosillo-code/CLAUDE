# Field Brief country rules

One JSON file per country, named by ISO 3166-1 alpha-2 code in lower case
(`pt.json`, `jp.json`), bundled offline like `lib/landmarks.ts` and registered
in `index.ts`. These files are the only source of legality statements in
Waypoint: the model never writes a rule, and a country without a file renders
as "not yet covered" (with its authority link when `../authorities.json` has one).

## Three tiers, labelled everywhere

- **`reviewTier: "verified"`** (the default) — a named pilot read the sources
  and has flown in that country. `verifiedBy` is their handle.
- **`reviewTier: "desk-review"`** — official sources read at a desk. The pages
  and the brief show the label *"Desk review of official sources — not yet
  checked by a pilot who has flown here."* `verifiedBy` is the review's own
  tag (`codex-source-review` for the September 2026 review of 31 EASA
  baselines and US, GB, JP, TH, SG), never a person's handle. The EASA
  baselines say only what the shared EU rules say (`coverage: "baseline"`).
- **`reviewTier: "unverified"`** — a general-knowledge summary written
  without fetching the sources, generated by
  `scripts/fieldbrief/unverified-countries.py` (September 2026, 66 countries).
  `verifiedBy` is `claude-general-knowledge`, `notes` ends with the sentence
  that says so, and every page and brief shows *"Unverified summary written
  from general knowledge — check the authority page before you fly."* The
  generator never overwrites a verified or desk-reviewed file. To fix a fact
  in one of these, edit the JSON directly: the generator keeps hand-edited
  files only if you also remove the country from its table.

### City notes

Any record may carry `cityNotes[]` — `{ city, note, reviewTier? }` for a
city, park or coast. A note inherits the record's tier unless it names its
own; a note inside an unverified record cannot claim a higher tier. The
country page lists them all and the brief shows the ones whose city name
matches the place being briefed.

To upgrade an unverified or desk-reviewed record to verified: read every statement against every URL
in `sourceUrls` plus the authority's current notices, fix or delete anything
you cannot confirm, set `reviewTier` to `"verified"`, `lastVerifiedOn` to the
day you finished and `verifiedBy` to **your** handle.

## The rule about rules

**A rule without a source and a date is not a rule.** Every file carries
`sourceUrls[]` (at least one), `lastVerifiedOn` and `verifiedBy`. The UI never
says "legal" or "allowed" — it says "as of {date}, per {source}". Older than
180 days renders with a stale warning; older than 365 fails the test suite.
Unknown is distinct from false: a flag's `value` may be `null` ("depends on
the operation") with the condition in its note; `maxAltitudeM` may be `null`
with an `altitudeNote`. Waypoint never claims airspace authority — no LAANC,
UTM or geofence checks; `nationalApp` points at the country's own tool.

## Adding a country

1. Copy `_template.json` to `{cc}.json` and replace every `example.invalid`
   placeholder with the real page.
2. Fill every field from primary sources you have read yourself. Do not paste
   a forum summary or a model's output.
3. Set `reviewTier`, `lastVerifiedOn` and `verifiedBy` honestly.
4. Register the file in `index.ts` and add an entry to `../authorities.json`.
5. Run `npm test` — `tests/fieldbrief-rules.test.ts` checks the schema, the
   sources, the date, the filename, the registry and the tier labelling.
